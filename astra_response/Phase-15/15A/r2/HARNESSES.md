# Physical test harness boundaries

The ordinary-source checks used Samsung My Files and its actual Android Sharesheet.
The manual-upload check used Android Photo Picker and DocumentsUI. No private
photos, seller content, Facebook surface or source-app screenshots were published.

The [fixture sender/provider](harness/fixture/src/com/abrianbaker/brickvault/phase15fixture/FixtureShareActivity.java)
is a separate package/UID with no network permission. Its private grantable provider
serves only generated bytes. Its visible case selector and Send button issue real
matching EXTRA_STREAM/ClipData intents. It verifies the exact debuggable TEST target
APK/signer before granting anything. Provider cases were run against eb18, whose
native/config payload is byte-identical to final fcc37bfe. Its direct explicit intents
prove receiver/grant behavior; My Files independently proves Sharesheet discovery.

[Provider revocation](harness/fixture/src/com/abrianbaker/brickvault/phase15fixture/FixtureProvider.java)
checks an actual granted permission, clears Binder caller identity, revokes its own
unique B URI and checks denial. It does not inject a target exception or change any
phone permission setting. The fixed test log tag contains only synthetic run/item
identifiers and grant outcomes. [Hashes](evidence/fixture-hashes.json) identify bytes.

The [final instrumentation test](harness/instrumentation/src/com/abrianbaker/brickvault/appraisal/phase15test/Phase15RecreationTest.java)
uses already-declared cached AndroidX dependencies and an ignored test source set.
It guards exact final TEST APK/signer/localhost configuration. It calls public
Activity.recreate using the actual resumed Activity, observes real lifecycle events,
and changes only that Activity's requested orientation, restoring its original value.
It does not patch the product APK, inject a testing SDK, change global phone settings,
fake Share state or call the application's session setters to create authorization.

CDP attached only to the target package's visible attached WebView. It drove normal
DOM controls, read native metadata without modifying it, observed HTTP requests and
injected one response-stage transport failure after a real server 201. No mocked
upload response or manually inserted receipt was used. Complete API observability
and persisted readbacks independently reconcile the writes.

The first intent-filter-dependent ActivityScenario test failed before recreation;
it was corrected with public lifecycle monitoring, and the final one-test run passed.
Build receipts retain that history separately from actual run evidence. Both helper
APKs were removed during cleanup. No test harness is part of the production sources
or installed final product APK.
