# Official Android findings — checked 2026-10-07

Bounded research used official Android documentation only. These are platform findings
and design inferences; none establish Facebook permission, installed package, source-app
Share support, overlay-free capture or physical compatibility. Device API is unknown;
the current app source targets/compiles 36 with minimum 24. No toolchain update is proposed.

| Topic | Supported behavior / constraint | Phase 15 implication and official source |
|---|---|---|
| Share receive | ACTION_SEND/SEND_MULTIPLE; MIME filters and stream payloads; recipient confirmation | Image-only receiver; explicit review, no automatic URL fetch. [Receive shared data](https://developer.android.com/develop/ui/compose/sharing/receive) |
| URI grants | Temporary content-URI permission flags; access tied to receiver task lifetime | Read while permitted; revoked/unreadable is an individual failure; do not assume persistable access. [File sharing](https://developer.android.com/training/secure-file-sharing/share-file) |
| Sender identity | Sender/caller details can be missing or voluntarily supplied | Never treat calling package as pixel provenance/security. [ShareCompat](https://developer.android.com/reference/androidx/core/app/ShareCompat.IntentReader#getCallingPackage()), [Activity](https://developer.android.com/reference/android/app/Activity#getLaunchedFromPackage()), [ComponentCaller](https://developer.android.com/reference/android/app/ComponentCaller#getPackage()) |
| Projection | API 21 display projection; API 34 user-selected single app, per-session consent and one-use virtual-display token | Single-app choice does not expose an enforceable package allowlist in documented public API; inference: projection alone fails this gate. [Projection guide](https://developer.android.com/media/grow/media-projection), [Manager](https://developer.android.com/reference/android/media/projection/MediaProjectionManager), [Config](https://developer.android.com/reference/android/media/projection/MediaProjectionConfig) |
| Foreground service | MediaProjection service requirements, target 34+ type/permissions, consent before service then getMediaProjection | No background/boot collection; approval and visible stop are necessary. [Service types](https://developer.android.com/develop/background-work/services/fgs/service-types#media-projection), [Manager](https://developer.android.com/reference/android/media/projection/MediaProjectionManager) |
| Background start | Target 31+ FGS starts constrained; target 35+ overlay exemption requires visible overlay | Visible control is required, not a way around background restrictions. [Background restrictions](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start) |
| Projection lifecycle | API 34 resize/visibility callbacks; onStop invalidates session; user/system stop, lock and process death release resources | Rotation/revocation cleanup; new consent after stop, no automatic restart. [Callbacks](https://developer.android.com/reference/android/media/projection/MediaProjection.Callback), [Projection guide](https://developer.android.com/media/grow/media-projection) |
| Accessibility screenshots | API 30 takeScreenshot(display); API 34 takeScreenshotOfWindow(windowId); declared screenshot capability and secure/invalid-window errors | Window API candidate only after accessibility-purpose suitability; whole display is too broad. [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) |
| Window identity | Interactive-window retrieval needs declared capabilities/flags; root node exposes package; packageNames filters events | Filter is not screenshot scope; request/callback window identity and races need proof. [ServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo), [WindowInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityWindowInfo), [NodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo#getPackageName()) |
| Overlay | TYPE_APPLICATION_OVERLAY API 26; SYSTEM_ALERT_WINDOW user permission, canDrawOverlays check; system can hide/reposition | Optional visible control, never capture/package proof. [Overlay type](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY), [Permission](https://developer.android.com/reference/android/provider/Settings#canDrawOverlays(android.content.Context)) |
| Protected windows | FLAG_SECURE excludes screenshot/nonsecure display; API 31 hide-overlay control | Protected/error/blank content and hidden controls are unavailable; no bypass. [Secure flag](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE), [Hide overlays](https://developer.android.com/reference/android/view/Window#setHideOverlayWindows(boolean)) |

Recommendation: 15A uses ordinary Share only. Keep 15B unresolved until the actual
phone/API/package facts, accessibility suitability or another supported enforced-target
mechanism, visible user control and race-safe target-change refusal are reviewed.
Physical tests then cover grant/revocation, protected window, rotation, target change,
disabled/restart state, one allowed successful result if supported, and manual/Share fallback.
